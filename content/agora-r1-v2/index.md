2026年4月、ChatGPTが東京大学の入試を解き、合格者の最高点を上回りました。前年には、国際数学オリンピックで金メダル相当の成績も出ています。**答えが決まっていて、採点のしかたも決まっている問題は、もうAIの領域です**。

では、その領域を極めた人間は、**答えのない問題**に向かったとき、何をするのか。

2026年7月、オンラインに5人が集まりました。六本木ベンチャーキャピタルが始めた<strong>「Agora」</strong>というプログラムの、第1回です。[Agora](/agora/)は、突出した若い才能が、AIと深く議論して、まだ世にない新しいものを生み出すプログラムです。

2時間の議論の末、5人とAIは、Kaggleには無かった出題の形に辿り着きました。**まだ世になかった形が1つ、そこで生まれました**。

その後、1か月間の開発の末、それは誰でも触れるものになりました。**できたプロダクトはこちらになります**。

## 1. なぜ「Kaggleの民主化」をしたいのか

山井さんがKaggleを知ったのは、高校1年の冬でした。偶然です。国際人工知能オリンピックという大会が存在することを知ったのは、日本予選の1か月前でした。そこから1年未満で、彼はメダルを取っています。

つまり、彼の側で足りていなかったのは能力ではありませんでした。**知る機会でした**。

では、何が入口を塞いでいるのか。本人が挙げたのは、教材の不足ではありませんでした。

{{< say who="yamai" >}}
一番難しいのは「<strong>自走力」</strong>かなと思っていて。自分で情報を集めたりとか、そういう作業が結構、参入障壁を高めているのかなと。Kaggle自体を知らない高校生の方がもちろん多いですし。**教材にしろメンターにしろ、方向性だけでも導いてくれるような存在は必須**かなと思います。

{{< /say >}}

同席したもう一人の高校生、聖光学院高校1年で副生徒会長の飯塚さんも、同じ場所でつまずいていました。

{{< say who="iizuka" >}}
やりづらかったのは、自分から一人でノートブックを作って、モデルをどんどん作っていく、**その知識や経験がそもそもないと、何から始めていいのか分からない**みたいな感じだったので。その点で結構、苦労しましたね。
{{< /say >}}

2人の感触では、同級生でKaggleを知っている人は1割に届きません。

**偶然に左右される状態は、才能の側の問題ではなく、設計の側の問題です**。彼が「民主化」と言ったのは、そこに向けてでした。

### 原理は学校で教えればいいのにな、と彼は話した

当日、参加者全員が一本の記事を見ながら議論していました。日経クロステックの連載[「日本、『1億総AI人材』への道」第1回](https://xtech.nikkei.com/atcl/nxt/column/18/03399/111000001/)です。IOAI 2025に日本から参加した4人が全員メダルを取ったことを伝えています。山井さんは、その4人の1人です。

記事の見立てはこうです。**AIをつくる先端の人材では、日本は海外にひけを取っていない**。足りていないのは、その先端を支える裾野 ── **AIを使う人の層の厚みである**。だから日本が全体として巻き返すには、一般の人材の底上げが要る。

その記事に、原理を学ぶ必要性の話は出てきません。山井さんが引っかかったのは、そこでした。

{{< say who="yamai" >}}
「いかに使うか」みたいなところが注目されがちですけど。もう少し専門的な知識というか、技術的なところまで踏み込んで教えてもいいのにな、とは思いますね。このLLM自体も、すぐに前提が変わっていってしまいそうなので、**その原理みたいな部分は、学校で教えればいいのにな**、とは思いますね。
{{< /say >}}

（LLM＝ChatGPTのような、文章を扱うAIのこと。）

## 2. 雑に聞いて、AIの答えを、先に見た

Agoraには前提となる仮説が1つあります。**AIは、雑に聞けば雑に答えがちだ**ということです。「いいアイデアを出して」と頼むと、どこかで聞いたような寄せ集めが返ってきやすい。誰が聞いても同じ、無難で平均的な答えになりがちです。**誰でも手に入る答えに価値はありません**。

だから議論の前に、その「雑に聞いた場合」を全員で見ておきました。使ったAIは Anthropic の Claude Fable 5 です。何の工夫もない指示を1行投げます。

{{< say who="yamada" >}}
Kaggleを民主化する新しいサービスのアイデアを考えて
{{< /say >}}

30秒ほどで、5案が返ってきました。

{{< say who="ai" >}}
Kaggleの民主化、面白いテーマですね。Kaggleの現状の課題を整理すると、「参入障壁が高い(統計・ML知識、英語、GPU環境)」「上位勢と初心者の断絶」「実務との乖離」あたりがボトルネックです。それぞれを崩すサービスアイデアをいくつかご提案します。

**1. 「Kaggle Sherpa」— AIメンター伴走型コンペプラットフォーム** ── 初心者がコンペに参加すると、AIエージェントが伴走するサービスです。EDA(探索的データ分析)を一緒に進め、「なぜこの特徴量が効きそうか」を対話で解説。公開Notebookを自動で日本語解説付きに変換。提出前に「このモデルのリークリスク」「CVとLBの乖離原因」を診断。差別化ポイント:答えを出すのではなく「考え方」を教える設計にすることで、単なる代行と一線を画す。

**2. 「Micro-Kaggle」— 1時間で完結するマイクロコンペ** ── Kaggleのコンペは数ヶ月がかりで、社会人には重すぎます。データセットを小さく、問題をシンプルにした「1時間コンペ」を毎日開催。スマホからでも参加可能(ブラウザ上のNotebook環境を提供)。Duolingoのようなストリーク・リーグ制で習慣化を促進。ビジネスモデル:企業のスポンサードコンペ(採用目的)。

**3. 「Kaggle for Domain Experts」— コード不要のコンペ参加** ── 医師、金融アナリスト、製造業エンジニアなど、ドメイン知識はあるがコードが書けない層を取り込みます。自然言語で仮説を記述 →「この検査値と年齢の交互作用が効くはず」→ AIが特徴量エンジニアリングとモデル構築を代行。ドメイン専門家とKagglerのマッチング機能(チーム戦の民主化)。ドメイン知識の貢献度を定量評価し、賞金分配に反映。

**4. 「実データKaggle」— 中小企業の課題をコンペ化** ── Kaggleに企業データを出せるのは大企業だけです。中小企業の課題(需要予測、不良品検知など)を、匿名化・合成データ化してコンペとして出題するSaaS。賞金は少額でも「実案件の実績」が参加者の報酬になる。企業側は低コストでPoC、参加者はポートフォリオを獲得できる三方良しの構造。

**5. 「Kaggle Replay」— 過去コンペのタイムマシン学習** ── 終了したコンペを「当時のLB状態」から再体験できる学習サービスです。上位解法を段階的にアンロック(自分のスコアを超えないと次のヒントが見えない)。「この時点でGrandmasterは何を考えていたか」を解法write-upと紐付けて追体験。資格・検定と連動させて企業の採用シグナルにする。

**私のおすすめ** ── 一番事業性が高いと考えるのは 4(実データKaggle)+ 3(ドメイン専門家の取り込み)の組み合わせ です。理由は:「民主化」の対象を参加者側だけでなく出題側にも広げている点が独自／合成データ生成技術(プライバシー保護)が成熟してきた今だからこそ成立する／収益源が明確(企業からのSaaS課金)で、賞金依存のKaggleモデルより持続可能。

特定のアイデアを深掘りしたり、ビジネスモデルキャンバスや技術アーキテクチャに落とし込んだりすることもできますので、お気軽にお申し付けください。

## 3. 2時間で、人が何を議論したか

### 対象を絞り込んだ ──「高校生」では広すぎた

最初にやったのは、誰の課題を解決するのかを決めることでした。「高校生」では広すぎる。上場企業を含む60社以上の事業推進や経営に携わり、39件の事業売却実績を持ち、元大手予備校数学講師の糸永季生さんが、教えてきた経験から線を引きます。

{{< say who="itonaga" >}}
一括りに「高校生」とするのは難しいと思っていて。トップ層と平均的な層では、前提がかなり違うんですね。ただ、本当のトップだけに限らなくてもよくて、**例えば偏差値60以上とすれば、数学や論理の力はもう十分あるので、Kaggleのような難しいものにも取り組めるはずなんですね**。そこまでは対象にしていいかなと。
{{< /say >}}

{{< say who="yamai" >}}
いいと思いますね。自分のまわりでも、その課題は感じるので。60以上でも結構、まあ大変かなとは思います。
{{< /say >}}

{{< say who="kitamura" >}}
要するに、**地頭はいいけど、プログラミングとかに触れたことがなくて、入りの敷居が高い人をどう取り込むか**。そういうことを狙っている、という意味で合ってますか？

{{< say who="yamai" >}}

### AIが全部やってくれるなら、壁はなくなるのか

ここで進行役が、こう問いました。

{{< say who="yamada" >}}
今はもう Claude Code など、AIコーディングエージェントがあるので、やりたいことを自然言語で言うだけで、AIが分析してコードを出してくれます。分からないところは「中学生でも分かるように教えて」と言えばわかりやすく解説してくれます。**それでも、ハードルって残ると思いますか**。
{{< /say >}}

{{< say who="yamai" >}}
そうなると、**最初の提出スコアが出るところまでたどり着く人は増えそうかなとは思いますけど。それで本当に理解して、Kaggleで学べてる人が本当に増えるのかな**、という。そこはまだ課題が残るんじゃないかなと思いますね。
{{< /say >}}

**「提出できる人」と「理解して学べる人」が、ここで初めて分離しました。AIが消すのは前者の壁だけです**。

{{< column n="1" title="AIに任せてよいのは、どこまでか" >}}
「中身を理解しないまま、AIにKaggleをやらせていいのか」という問いは、Agora議論終了後に進行役がAIと相談して整理しました。そこで出た結論は、「やらせてはいけない。ただし全部理解しろというのも間違いで、<strong>理解には人に任せていい層と、任せられない層がある」</strong>でした。

**① 道具の中身** ── 出来合いの道具が内部でやっている計算や数式。**AIに任せてよい**。専門家も詳しく中身を見ていません。車を運転するのにエンジンの理屈は要らないのと同じです。

**② 手続きが正しいかどうか** ── データの整え方、答えの漏れ込み、採点のやり方、練習データに合わせすぎていないか。**ここが急所です**。

**③ 結論が正しいかどうか** ── 出てきたものを「これで正しい」と受け取ってよいか。**ここは任せられません**。理由は1つで、**正しさの基準を、AIは自分では決められない**からです。だから自信のある口調で間違えますし、自分で書いたテストを自分で通して「問題ありませんでした」と報告してくることもあります。分析でも同じで、2つの数字が一緒に動いていれば、それを原因のように語ります。相関関係と因果関係は別ですが、そこを分けるのは人間の仕事です。しかも専門家でも意見が割れます。

② 手続きが正しいかどうか ── これが急所である理由は、難しいからではありません。②を間違えても、結果の見た目にはそれが出ないことがあるからです。しかも、悪いほうに出るとは限りません。

それが実際に起きた記録が1つあります。 Kaggle Competition Master で、Metaの機械学習エンジニアである Andrey Lukyanenko 氏が、2026年7月に公開した[記録](https://andlukyane.com/blog/kaggle-antigravity-s6e7)です。**AIエージェントに、Kaggleのコンペを丸ごと走らせています**。Agora議論終了後に、進行役が調べました。

{{< fig n="3" src="img/agora/r1/fig-agent.svg" src-sp="img/agora/r1/fig-agent-sp.svg" >}}人間が渡したのは、指示文1枚と、決めごと3つだけ。{{< /fig >}}

**① 道具の中身 ── この層は、全部AIがやりました。** 課題は、健康診断の記録63万人分から、一人ずつ「要注意」か「問題なし」を見分けるものです。AIは、データの下調べをし、予測の手がかりになる列を自分で約140個作り、3種類のモデルを並行して学習させ、その混ぜ方まで自分で調整して、提出まで自力でやりました。人間は、プログラムをほとんど書いていません。列の中身も、モデルの中で何が計算されているかも、人間は見ていません。それで動きました。

**② 手続きが正しいかどうか ── この層で、止まりました。** AIは、自分がうまくできているかを、自分で確かめながら改善を進めます。その確かめ方が、この課題と合っていませんでした。100人に縮めて書きます。

```
 100人を「要注意」と「問題なし」に振り分ける。
 実際の内わけは、こう偏っている

    要注意   94人  ●●●●●●●●●●●●●●●
    問題なし  6人  ○
```

```
 AIが使っていた数え方
    「100人のうち、何人当たったか」

 この課題で求められていた数え方
    「要注意の人を見つけられたか」と
    「問題なしの人を見つけられたか」を、同じ重さで見る
```

この違いが、AIの判断を片側へ引っぱります。

```
 判断に迷う一人が出てきたとする。どちらと答えるか
```

AIの訓練で目指しているものは、3つです。順番に足していきます。**① 見たものをなぞる**（材料はインターネットの文章。次の1語を当てる練習）／**② 人が好む方へ寄せる**（材料は、AとBの2つを人に見せて、良いと思ったほうを選んでもらった記録。選ばれた方に高い点が付くようにする練習）／**③ 機械で正誤が付くものを当てる**（材料は数学とコード。正解と合っているかを機械が採点する練習）。

**①でよく誤解されることがあります**。AIは「よく見る語を好め」と教わってはいません。珍しい語にも正しい確率を付けるように鍛えられます。出てくる文が無難になるのは、この練習のせいではありません。**聞き方の条件が薄いと、確率がよく見る言い回しに集まり、しかも出すときに高い山を選びやすくしているから**です（→ コラム4）。

{{< fig n="4" src="img/agora/r1/fig-reward.svg" src-sp="img/agora/r1/fig-reward-sp.svg" >}}上段は訓練で目指している3つ。下段の棒の長さは説明のための模式で、人数の実測ではない。{{< /fig >}}

**この3つに、「これは価値ある新しさか」を測る物差しはありません**。①には「見た通りか」、②には「人が良いと思ったか」、③には「正解と合っているか」があります。新しさを測るものだけが、どこにもないのです。

ここで、②があるじゃないか、と思うはずです。「どちらが良いか」は機械では採点できないのに、人に選ばせて報酬にした。同じように「どちらがより新しいか」を選ばせればいい。理屈としては、できます。できるのに効かない理由は、別のところにあります。

**本物の新しさは、出てきた時点では、少数の人にしか価値が分かりません**。多数決で点を付けると、いちばん低い点が付きます。①は平均をなぞり、②は多数決に寄せる。2つとも、同じ方向へ働きます。

残るのは③ですが、③が使えるのは正解表が書ける場所だけです。「2 + 3 = 5」には機械が正誤を付けられますが、「この問いは面白いか」には付けられません。**何を創るに値するかは、後者です**。だから③にも載りません。欠陥ではありません。構造です。

AIが人間を超えた例を並べると、同じものが見えます。採点表を作ったのは、どれも人でした。

| | 採点表を作ったのは |
|---|---|
| **AlphaFold** | 人（予測した形を、実験で分かった形と比べる）|
| **AlphaTensor** | 人（掛け算の回数を数える。少ないほど良い）|
| **AlphaZero** | 人（将棋のルールと、勝ち負けの決め方）|

**AIがやったのは、その採点表の中で点を上げることでした**。AlphaZeroは自分で何百万局も指して、自分で練習相手を作りました。自分で問題を作ったように見えます。それでも、ルールと勝ち負けの決め方は人が置いたままです。動かしていないのは、そこです。

人の仕事は、問題と採点の仕組みを、前もって作ったところまででした。

**この2時間が置かれていたのは、その真逆の場所です**。答えを検算できず、報酬がどこにも無く、選別は人間がその場で1個ずつやる。候補は蛇口を全開にすれば何千個も出ます。だから創造の正体は「無から生む」より <strong>「膨大な候補から、稀な意味あるものを選び抜く」</strong>ことになります。

ただし「AIは創造できない」は言い過ぎです。正確には「**価値ある新しさを、自分で狙って、自分で判定することができない」**。狙いと判定を外から入れれば、本物の発見に届きます。AlphaFoldは、そうやって届いた例です。

### プロダクトの特徴

**1. 対話で読みながら、そのまま自分で動かせます**

博士と高校2年生のやり取りで進みます。説明を読むのではなく、会話を追っていくと分かる形にしました。

対話形式でわかりやすいAIの入門書も、触って動かせるAIの可視化ツールも、一問ずつ出題して採点してくれる演習サイトも、すでに世の中にあります。**ただし、3つを兼ねたものは見つかりませんでした。だから作りました**。

|---|---|---|---|

| AIの可視化ツール（Transformer Explainer など） | ✗ | ○ | ✗ |
| 一問形式・自動採点の演習サイト（Deep-ML など） | ✗ | ○ | ○ |
| **Deep Black Box** | ○ | ○ | ○ |
{{< /wide >}}

{{< fig n="10" src="img/agora/r1/shot-q1q2.png" wide="1" >}}各問は博士と高校生のやりとりで始まり、そのあと自分で動かします。問1では、つまみを2つ動かすと線が点に近づき、ずれの点数がその場で返ります。問2では、そのずれを地形にして、いちばん低い場所へ向かって下ります。{{< /fig >}}

**2. 全21問、自分で手を動かします**

読むだけの問題は1つもありません。多くの問題には**つまみ**（左右に動かすスライダー）が並んでいて、動かしているのはAIの中身の数値そのもの、つまり**パラメータ**です。つまみのない問題は、ボタンで切り替えたり、3択で先に予想したりする形になります。

**3. 画面の数字は、すべて実測値です**

AIは難しいので分かりやすく書く必要がありますが、分かりやすくしすぎると正確ではない表現になることがあります。だから機構は原論文32本に紐づけました。[原論文から解き明かす生成AI](https://www.amazon.co.jp/%E5%8E%9F%E8%AB%96%E6%96%87%E3%81%8B%E3%82%89%E8%A7%A3%E3%81%8D%E6%98%8E%E3%81%8B%E3%81%99%E7%94%9F%E6%88%90AI-%E8%8F%8A%E7%94%B0-%E9%81%A5%E5%B9%B3/dp/4297150786)という本で紹介されている原論文32本を参照しています。そして、このゲームのために簡単にした場所は「ここは簡単にしました」と書いてあります。

**4. 準備がいりません**

インストールも環境構築も不要。ブラウザで開くだけ。スマートフォンでもできます。
